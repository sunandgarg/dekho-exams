# AI Trove Python source kit

398 original teaching programs. Each file's minimum syntax is recorded in manifest.json; most use the Python 3.11 grammar, while newer language features may require a later release. Execution and exact displayed outputs were checked on CPython 3.14.6. Parsing with an older grammar is not a runtime test on that older interpreter. Programs with third-party imports were checked on CPython 3.14.6 with the package versions listed in manifest.json. No older-runtime compatibility is claimed for those dependency sets.

Create a dedicated environment with `python3 -m venv .venv`, then install the recorded test environment using `.venv/bin/python -m pip install -r requirements.txt` on POSIX or `.venv\Scripts\python.exe -m pip install -r requirements.txt` on Windows. requirements.txt pins the tested environment; it is not a cross-platform wheel lock or a hash-verified supply-chain guarantee. Third-party packages retain their own licences and are not bundled here. Run one file with the environment interpreter and `-I`, for example `.venv/bin/python -I numpy_views.py`.

Run the contract, expansion, depth, completion, applied, service, lifetime, assurance, workflow, boundary and integrity suites with the recorded environment interpreter using `-I`. Each suite states its independent comparison counts in its source. manifest.json records every program's page, filename, dependencies and verified output.

Programs are independent teaching fixtures. Some print on import. Task groups use no external network. The SQLite project uses a temporary database file and checks a clean reopen, while other ledgers remain in-memory. The file project checks staged replacement in an owned temporary directory; crash/power-loss durability is not claimed. Flask/Django use local test clients/forms and owned SQLite schemas; the migration fixture generates/applies an owned temporary app migration. They do not listen on a network port. A sequential replay ledger does not establish exactly-once external delivery. Data/model fixtures use small owned inputs; they do not claim predictive business quality. Pytest and mypy execute owned files locally. Packaging fixtures build owned wheels offline, install them or editable sources into fresh temporary targets, and verify fresh imports; they do not install into system/project site-packages or publish a release. The outbox writes state and pending events atomically; separate claim/renewal fixtures check two SQLite connections, token ownership and stale-state rejection. They do not establish remote exactly-once delivery, deployment clock correctness or production worker load. The plugin fixture loads trusted owned code, not arbitrary received programs. No credential, hosted code judge or deployment is provided. Timezone examples require host IANA data or the pinned tzdata fallback.

The native-extension fixtures compile and import their own temporary C sources on the checked macOS CPython 3.14.6 runtime. Their Linux command branches, Windows builds, cross-version abi3 imports, and a disabled-GIL interpreter were not tested here. POSIX process-group and undecodable-filename examples have platform-specific contracts. The archive includes C source embedded in teaching programs, not prebuilt binaries or distributable extension wheels.

The byte-stream fixtures feed owned data to StreamReader without opening a socket; they do not verify real peer deadlines or transport-wide buffer budgets. SQLite authorizer, progress, and SQL-length settings apply to individual connections and are not a sandbox. The mmap and scandir fixtures use owned temporary files on the checked macOS runtime. Their output does not establish crash durability, hostile filesystem race safety, or identical behavior on every operating system.

The received-input fixtures keep pickle loading behind an owned-data boundary; the JSON, query-string, email and configuration parsers check only their stated small record contracts. The email programs do not send messages or authenticate a sender. The socketpair program exchanges bytes locally without a remote host or TLS. The descriptor and O_NOFOLLOW program was checked on POSIX, and its final-component rule is not a complete path-security design.

The thread and asyncio lifetime fixtures use local, in-memory resources and a single owned worker thread. Cancelling an await of `asyncio.to_thread()` does not stop the already running thread function; the examples coordinate its release explicitly. Eager task execution was checked on CPython 3.14.6. Its recorded Python 3.12 minimum is a syntax/API availability boundary, not a claim that the example was run on 3.12.

The state-boundary fixtures use small, owned receipt data. The SQLite row-factory case rejects duplicate result names but does not authorize SQL. The queued-logging case uses an unbounded local queue and explicitly stops its listener; it does not establish backpressure under service load. Decimal rounding is a stated sample policy, not a universal money rule. The thread-barrier case checks abort behavior for one local worker, not distributed coordination.

Explanations and programs were written for AI Trove. Python syntax, API behavior, algorithmic facts and third-party projects are not exclusive AI Trove property. This archive includes no interpreter, dependencies, compiled bytecode or private configuration.
